# TractorCompare AI v22.1 — Fendt source fallback

## What changed
- Adds a narrow fallback only for brand `Fendt` and exact catalog model name `724 Vario`.
- Uses the official first-party Fendt technical-data endpoint:
  `https://api.fendt.com/techdata/GB/en/1551551`
- The endpoint identifies the Fendt 700 Vario Gen7.1 series and contains a dedicated 724 Vario model column.
- The extraction prompt restricts findings to the 724 Vario column and labels every value with `Generation: Fendt 700 Vario Gen7.1`.
- Since the current catalog row has no model year or generation, the fallback does not generalize these values to Gen7 or Gen6. Every finding remains pending human review.

## Deployment
- This is an Edge Function-only update. The v22.0 database migration already applied by the operator remains the required schema.
- No new SQL migration is required.
- Deploy `indexim-v22.1.ts` as the existing research Edge Function, replacing the current v22.0 code.

## Retry the failed single queue item
After the new Edge Function is deployed, the existing failed run remains in `ai_research_runs` for audit. Re-queue only the same queue row by clearing its pointer to the failed run; do not delete the old run:

```sql
UPDATE public.tractor_research_queue
SET
    status = 'queued',
    last_run_id = NULL,
    last_error = NULL,
    next_attempt_at = now(),
    completed_at = NULL,
    updated_at = now()
WHERE id = '5bb842e8-9017-40d4-b56c-3b336aa963e9'
  AND status = 'needs_source'
  AND last_run_id = 'a4b5c77c-ce0c-4d8e-ad25-75fd6a83c3c4'
RETURNING id, status, attempt_count, last_run_id, next_attempt_at;
```

The WHERE clause deliberately requires both the exact queue ID and the failed run ID so unrelated queue work cannot be changed.
