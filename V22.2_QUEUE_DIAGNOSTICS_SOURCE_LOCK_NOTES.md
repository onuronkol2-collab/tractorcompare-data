# TractorCompare AI v22.2 candidate

Date: 2026-11-15

## Purpose
Based on v22.1; addresses the Fendt 724 Vario live validation and diagnosis path.

## Changes
1. Adds `diagnose_queue_run` behind the existing `x-queue-secret` authorization.
   - Validates run UUID.
   - Requires a queue row whose `last_run_id` equals the supplied run ID.
   - Confirms the research run's `tractor_id` matches the queue row.
   - Reads queue state, run state, source-document metadata and current Gemini interaction diagnostics.
   - Does not update queue, run, source-document or finding records.

2. Adds a strict allow-list for newly started Fendt 724 Vario research.
   - Accepts only `https://api.fendt.com/techdata/GB/en/1551551`.
   - Requires HTTP 200, the official Gen7.1 scope note and exact 724 Vario identity evidence in fetched text.
   - Requires exactly one accepted packet; otherwise the run fails safely before Gemini is called.
   - Other Fendt pages (including Fendt 1000 Vario and 1100 Vario MT pages) are not persisted for this model and are not sent to Gemini.
   - Existing Gen7.1 prompt scope and mandatory human review remain.

## Preservation and deployment
- No SQL migration is required.
- No historical documents or findings are deleted or rewritten.
- The already-running v22.1 Gemini interaction and its four saved documents are not changed by this candidate.
- Automatic approval remains disabled.
- Deploy `indexim-v22.2.ts` as the Edge Function entrypoint before using the new action.

## Read-only diagnosis test
Send POST with headers:
- `Content-Type: application/json`
- `x-queue-secret: <TC_QUEUE_SECRET>`

Body:
```json
{
  "action": "diagnose_queue_run",
  "run_id": "2d07e8d3-26a0-4d0a-a451-4d115cb42aed"
}
```

This only reads the queue-linked run and asks Gemini for its interaction state. It does not increment queue attempt_count.
