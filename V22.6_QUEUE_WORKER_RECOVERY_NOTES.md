# TractorCompare AI Edge Function v22.6 — Queue Worker Exception Recovery

Date: 2026-11-15
Branch: `candidate/v22.6-queue-worker-recovery-2026-11-15`
Base: v22.5 exact-source rules

## Purpose

v22.5 can claim a queue row and then leave it in `running` with `last_run_id = NULL` when an unexpected exception occurs before the atomic run-open RPC completes. That makes subsequent targeted requests return HTTP 409 until the stale-running reclaim window, and another worker can race to claim the row again.

## v22.6 change

- Wrap all post-claim work in `processQueue` with an exception recovery path.
- On an unexpected exception, retry the row with exponential delay (capped at 60 minutes), or mark it failed only when `attempt_count >= max_attempts`.
- Store the underlying exception in `last_error` with the marker `TC_QUEUE_WORKER_EXCEPTION_V22_6`.
- Recovery is compare-and-set guarded by queue ID, `status = 'running'`, and the original claim `updated_at`.
- The atomic `tc_open_or_reuse_tractor_research_run` RPC updates `updated_at` while linking `last_run_id`; therefore, if another phase has advanced the lease/run, the recovery path does not overwrite it.
- Existing run IDs are not reset. Existing research history, source documents, findings, and published tractor rows are not deleted or rewritten by this recovery change.
