# TractorCompare AI Edge Function v22.7 — modelKey scope fix

Date: 2026-11-15
Branch: `candidate/v22.7-modelkey-scope-fix-2026-11-15`
Base: v22.6 queue worker recovery

## Root cause

The queue error `TC_QUEUE_WORKER_EXCEPTION_V22_6: modelKey is not defined` was traced to `chooseSource()` in the Edge Function.

`modelKey` had been declared with block scope inside the `else` branch that ranks stored sources, but the curated exact-model source-lock conditions below that branch also referenced `modelKey`. When a request used the explicit/forced source path, the outer code referenced an undeclared identifier and threw a ReferenceError before creating an `ai_research_runs` record.

The same scope defect was present in the v22.5 source. v22.6's new queue exception handler made the failure visible in `last_error` and safely moved claims to retry; it did not introduce the underlying `modelKey` reference.

## v22.7 fix

- Declare `const modelKey = normalise(modelName)` once in the outer `chooseSource()` function scope.
- Remove the inner block-scoped declaration.
- The explicit source and stored-source paths now share the same normalized key for the curated source locks.
- Retains v22.6 compare-and-set queue exception recovery.
- Retains v22.5 source rules:
  - Case IH Farmall 110A: official 2025 Farmall A brochure (`v644d87af`).
  - Fendt 516 Vario: official Fendt 500 Vario Gen4 technical endpoint.
  - Deutz-Fahr 6165 TTV: official 6 Series technical PDF.
  - Existing Puma 150 EMEA and Fendt 724 Gen7.1 safeguards.
- Automatic approval remains disabled.
