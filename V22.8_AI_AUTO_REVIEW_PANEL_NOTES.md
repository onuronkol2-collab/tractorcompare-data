# TractorCompare AI v22.8 — Evidence-gated auto approval and review panel

**Status:** Candidate only; not deployed to production.  
**Base:** `candidate/ai-extraction-benchmark-2026-11-15` / v22.7.  
**Candidate branch:** `candidate/v22.8-ai-auto-review-panel-2026-11-15`

## What this change is for

The AI remains the primary research and data-extraction engine. It can approve individual technical findings automatically when the exact tractor identity, official source, evidence, page, variant and semantic quality checks all pass. Findings that are ambiguous or conflict with the source remain in the review queue. A single suspicious finding does not hold back other independently verified findings for the same tractor.

A tractor model itself is not automatically published by this feature. Approved findings can be written to `tractor_specs` for an existing model; a new/draft tractor remains draft until the separate model-publication workflow is completed.

## Automatic approval policy

The default is enabled in this candidate. Set the Edge Function secret `TC_AUTO_APPROVE_VERIFIED_FINDINGS=false` to run in review-only mode. Remove the secret (or set it to anything other than `false`) to enable the policy.

Every individual finding must pass all of the following:

- Exact model identity and any requested variant/year/market check.
- Exact document-specific identity metadata: model and requested variant keys must match.
- First-party manufacturer source or a narrow brand-specific official asset host; source HTTP 200, model-specific document, source priority at least 85 and relevance at least 90.
- Evidence text must contain the proposed value; PDF findings must have a page number.
- Evidence-support score at least 0.985. This is only one gate; it is an LLM-reported score, not a calibrated probability.
- Semantic risk checks must be clear: shipping/ROPS/cab/ballast vs operating weight; rated/max/gross/net/boost/IPM/DP/EPM power; total/implement/steering hydraulic flow; PTO shaft speed vs engine RPM; hitch capacity at link ends vs 610 mm/24 in behind; 2WD/4WD mixing; displacement unit mismatch; inconsistent printed kg/lb pairs.
- Existing human-managed `tractor_specs` are never overwritten by the AI auto-approval path.

Each decision is stored in `ai_research_findings.quality_meta`. The reason a finding was held is stored in `risk_flags` and `review_notes`.

## Review panel

Static page: `admin/ai-review.html`

Features:
- Turkish interface with pending, approved and rejected tabs.
- Review counters including AI-approved findings.
- Exact tractor/model/variant context, source PDF/page link, HTTP status and source priority.
- Visible AI risk flags and evidence quote.
- Edit spec name/value/unit, evidence quote and page, then save as a human-managed finding.
- Approve or reject a finding; bulk-approve selected pending rows.
- Correct the value, unit, evidence quote and PDF page; the corrected value is protected as human-managed.
- A simple administrator approval keeps AI management enabled, so later official-source refreshes can still update the value safely.
- A separate read-only **İşlem geçmişi** tab shows AI/admin actions; undo is offered from the current finding card to avoid undoing an older historical event by mistake.
- Writes an audit record to `ai_review_events`.

The page uses only the Supabase project URL, the public/anon key and a signed-in user's JWT. **Never put `DB_SECRET_KEY`, `service_role`, `TC_QUEUE_SECRET`, or a Gemini key in the page.** The Edge Function authenticates the JWT and checks `app_metadata.tc_research_admin=true` (or the existing admin role claims) before it serves review actions.

## Deployment order (do not skip)

This branch is not live. Do not copy the HTML to a public site or deploy the Edge Function before the SQL migration is applied.

1. Back up the currently deployed `tractor-ai` Edge Function and note its deployed version.
2. Review and apply `supabase/migrations/202611150003_tc_v228_ai_review_panel.sql` in Supabase SQL Editor. It adds a JSONB quality metadata column and a service-role-only audit table. It does not update existing findings/specs.
3. Deploy `indexim-v22.8.ts` as the existing `tractor-ai` Edge Function's `index.ts`. Retain the current Supabase/Gemini secrets; add `TC_AUTO_APPROVE_VERIFIED_FINDINGS=false` only when deliberately choosing review-only mode.
4. In Supabase Dashboard → Authentication → Users, open the administrator account and ensure its **app metadata** includes `{"tc_research_admin":true}`. Do not place this in user-editable metadata. Sign out and sign in again after the claim is updated.
5. Host `admin/ai-review.html` in a private/admin-only area of the website (or a protected static host). It must be HTTPS. Do not publish it as a normal public navigation page; access is still protected server-side, but hiding the route reduces unwanted discovery.
6. Open the page and enter the Supabase project URL, public/anon key, and the administrator's normal email/password. The URL and public key are stored in that browser only; the password is handled by Supabase Auth.
7. Run `supabase/verification/verify_v228_ai_review_panel.sql`. Then test with one known pending finding: view, approve, edit-approve, reject and undo. Verify a normal non-admin JWT receives HTTP 403.

## Important validation caveat

The November 15 benchmark used `gemini-3.6-flash`. The v22.7 production candidate currently uses `gemini-3.8-flash` with `gemini-3.7-flash` fallback. The model/version difference means the benchmark does not prove identical extraction behavior. The deterministic gates reduce semantic risk, but test the deployed model against the same gold PDF set before enabling automatic approval for the first production run. Start with review-only mode if that comparison has not been completed.

## Rollback

- To disable automatic approval without redeploying code, set the Edge Function secret `TC_AUTO_APPROVE_VERIFIED_FINDINGS=false`.
- If the panel/API needs to be rolled back, restore the backed-up Edge Function version and remove the hosted panel route.
- Do not drop `ai_review_events` or `quality_meta` as a quick rollback; they contain audit history. The migration is additive and can safely remain in place while the previous Edge Function runs.
- Manual panel edits set `managed_by_ai=false`, preventing a later AI run from silently overwriting a value you corrected.
