# Assisted forum draft handoff (free, owner-mediated)
This change intentionally does not impersonate an account, mint a JWT, bypass RLS, or publish as an administrator. Production's rate-limit trigger requires auth.uid() matching the author. A local JSON file supplies editable content only; the account holder signs in normally, imports and reviews it, and clicks the existing publish button. Translation consent is never imported. The existing authenticated Supabase insert, constraints, quotas, moderation and public verification are unchanged.
Schema: { "version": 1, "title": "...", "body": "...", "category": "questions", "locale": "tr", "tractor_id": "" }. The optional tractor_id must be a real published catalogue selection. No credentials, author ID, publishing status, or consent fields are accepted.
Acceptance before merge: unit tests; real browser test with signed-in fixture: invalid JSON rejected; existing draft not overwritten; logout during file read prevents import; import itself makes no write request; ordinary publish uses verified session and normal API; consent defaults false; mobile and 10 locales; existing RLS, rate limit, and translation tests unchanged. Do not claim automatic posting or deployment until verified. A fully delegated publishing feature would require a separately reviewed, revocable, account-authenticated grant and audit design; never fake auth.uid() or weaken the existing trigger.
