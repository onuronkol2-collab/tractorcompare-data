# Conversation-triggered source expansion (2026-11-24)

Apply on every authorized TractorVS development request, not only hourly tasks. The offline source planner complements (does not replace) the existing free OEM collector, PDF column review, private review staging, and photo discovery.

## Execution

1. Read current AGENTS.md, open PRs, actual live catalogue/readiness and prior completed evidence. Use the existing SQL private readiness view and exact source links; do not publish the input. Normalize source associations by exact UUID and URL, not raw spec count.
2. Run `node scripts/tractor-batch-source-plan.mjs /tmp/tractorvs-plan-UNIQUE.json < PRIVATE_SNAPSHOT.json` locally with an explicit ISO snapshot time, rows and optional review history. Store private input and output under a protected temporary location, never in the public repo or Actions artifact. Each row: tractor_id, brand, model, variant, market, model_year, status, readiness, source_url, optional document_sha256. Include a null source row for a genuinely linkless draft. History: source_url, status reviewed/rejected, tractor_id, document_sha256, reason; or status cooldown and retry_after. Use actual observed source revision and evidence only; never mark a model approved from planner output. No overwrites. CLI prints aggregate counts only.
3. Take largest marginal distinct model coverage first; readiness weights break ties. Independently blocked sources do not block other documents. Same document SHA and exact UUID review can be reused; changed hash or unknown version requires review. A provider-wide stop must still stop requests to that provider; the planner does not initiate any request.
4. Research additional source families: manufacturer series and regional product indexes, official brochures and operator manuals, public government test repositories, OECD tractor test reports, Nebraska Tractor Test Lab, DLG PowerMix, agricultural university collections and reliable independent technical publications. For brands without linked sources, use grouped brand discovery output and inspect original sources; a list/search result is not a verified specification. Use document hash, edition, model column, market, unit and standard for every claim. Do not copy paywalled text or restricted datasets. For model expansion compare existing UUID/brand/model/year/market/variant; no duplicate generic series records.
5. For photos: Wikimedia file/category/caption/photographer searches, Openverse Flickr/Europeana, public-domain institutional archives and explicit manufacturer media grants. Verify actual model badge/variant and original rights; no stock images, inferred permission or generator placeholders as real photos. Reuse the existing batch photo report and original SHA evidence across independent models; only exact eligible published targets. Prioritize never-photographed records, no repeated provider calls during cooldown.
6. Release multiple source-backed models/specifications/photos per safe packet; never weaken CI, RLS, ten-locale SEO, source and licensing requirements. Report reviewed vs published vs live counts separately. Track unique documents, marginal models and actual output; if an inaccessible source stalls progress, select next independent group. No paid calls, external communications or schedule changes without separate authorization.

This planner does not execute searches, SQL, imports, or deployment. It is not a guarantee of new sources or throughput. Use the existing private data pipeline for actual review and release.
