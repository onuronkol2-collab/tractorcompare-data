# Evidence-based automatic nominal catalogue release — 2026-11-25

Owner-approved policy: routine human review and a second user approval are not mandatory for nominal technical catalogue data. This is a narrowly scoped release decision, not a blanket approval of draft rows. Never fabricate human review, independent verification, source retrieval, model identity or evidence. Keep all security, copyright, editorial/translation/moderation, 2026 reliability, and independent field measurement gates.

## Evidence, not a label
Read actual manufacturer technical sources or trustworthy original independent technical specifications. Verify brand, model, market, variant, year if stated, options and measurement conditions. Each retained claim has an exact source URL, publisher, source type, page/table locator, excerpt, checked date, value/unit (explicit null for non-dimensional values), measurement standard and scope note. Store a source hash only if actual source bytes were obtained. Keep documented conflicts out of the public result; never infer a year, price, sales availability or photograph license. Announcement-only models must be labelled as announced, not available for sale. Require at least eight distinct verified technical concepts, unique active model identity, and all existing RLS, coverage, locale/SEO, source, quality and release tests. Independent nominal specifications require genuine independent evidence; measurements, superiority, reliability and failure claims do not enter the automated nominal lane.

## Executable decision
Use the existing private batch command:
`node scripts/tractor-catalogue-batch-review.mjs < private-candidates.json`.
Set `reviewMode: "automated_nominal"` and `modelGates.requiredReview: "not_applicable"` only under this owner-approved nominal policy; pending/failed existing review cannot silently pass. All other existing model and claim gates remain. The new `automatedEvidence` manifest contains `decisionType: "automated_evidence_review"`, `checkedOn` (YYYY-MM-DD), `rows` (one per retained claim), `omittedKeys`, `omissionVerified: "pass"`, `reviewedFingerprint`, and `currentFingerprint`. Each row contains key, claimType, value, unit, measurementStandard, sourceUrl, sourceType, sourcePublisher, sourceLocator, sourceExcerpt, sourceCheckedOn, scopeNote, exact modelIdentity (brand/model/market/variant/modelYear), and optional actual sourceSha256. Use `nominalEvidenceFingerprint` to bind those values and omitted keys. Reconstruct the current manifest from actual DB row values, stored evidence and the freshly verified source scope immediately before release; do not copy a reviewed fingerprint into currentFingerprint as a substitute for reading the current rows. A hash proves equality of supplied data, not source authenticity. The offline helper has no network or write access; it cannot independently verify provenance or publish. Record actual evidence and its limitations privately. Never supply synthetic pass statuses in real work. Do not commit unpublished model identities or private evidence.

The `automaticRelease` queue and `automaticReleaseEligible` are the automated evidence decision, not a database change. Only eligible exact UUIDs enter the existing serializable transaction: re-read and lock identity, retained specs and sources, confirm fingerprint/expected rows and duplicate/conflict checks, backup originals, simulate public view under anon in a rolled-back transaction, confirm held rows are excluded; commit only if the actual decision still matches. Trigger existing GitHub publication checkpoint/sync and all mandatory CI. Verify exact Cloudflare production SHA, all ten model URLs, source links, canonical/hreflang/sitemap and actual public content. If a required gate fails, isolate the model or roll back scoped changes; no broad promotion. The private readiness v1 label HUMAN_RELEASE_REVIEW is a legacy structural triage candidate, not an actual approval or a new human-review obligation for nominal data. Preserve it for backward compatibility; do not rename by editing an already-applied migration.

Photo workflow: no additional routine person approval, but actual visual identity/trim evidence, explicit commercial reuse/derivative rights, attribution, original bytes/hash, decode/MIME, asset and production tests remain mandatory. Missing photo does not block qualified technical records. No change to special human/independent approval or legal constraints for other content. All operations stay within free tools; never bypass CodeQL, RLS, copyright or external access limits.

Regression: `node --test site/tests/tractor-split-evidence-review.test.mjs`. Tests use synthetic fixtures only; CI success is not evidence that any real tractor passed or is live.
